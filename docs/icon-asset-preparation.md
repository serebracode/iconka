# Подготовка комплекта изображений икон

Этот алгоритм задаёт единый пакет для каждой иконы. Один исходник не
используется одновременно для каталога, экрана и режима свечи: у задач разная
геометрия, вес и требование к прозрачности.

## 1. Отбор исходника

1. Проверить резкость, отсутствие сильной JPEG-каши, корректность цвета и
   наличие полной доски иконы в кадре.
2. Если исходник слабый, сначала подобрать более качественную репродукцию.
   Обтравка не лечит плохую фотографию.
3. Выровнять кадр: без случайных полей, но с сохранением всего физического
   края доски, потертостей и неровностей. Их нельзя срезать «для красоты».

## 2. Единая мастер-альфа

1. Из исходника вырезать фон по реальному контуру иконы.
2. Сохранить прозрачность по краям доски, включая сколы и неровности. Белый,
   чёрный или цветной прямоугольник вокруг иконы недопустим.
3. Проверить результат на шахматном фоне и на чёрном фоне. Если по краю
   заметен ореол, маску доработать до экспорта остальных файлов.
4. Экспортировать мастер в `icons/png/<slug>.png`.

`cutout_master` — единственный источник альфа-канала для тени и эффектов
режима свечи. В коде нельзя строить тень по JPEG или по размеру исходного
файла.

## 3. Производные файлы

Для каждой иконы нужны пять файлов.

| Назначение | Путь | Формат | Правило |
|---|---|---|---|
| Карточка каталога | `icons/preview/<slug>_preview.jpg` | JPEG | Квадрат 160×160 px, `object-fit: cover`, лёгкое сжатие. |
| Прогрессивная загрузка | `icons/loading/<slug>_loading.jpg` | JPEG | Полный кадр с сохранением пропорций; длинная сторона 48 px. На экране иконы он намеренно растягивается крупными пикселями до прихода обычного JPEG. |
| Обычный экран иконы | `icons/<slug>.jpg` | JPEG | Полный кадр иконы; длинная сторона не больше 600 px для нового пакета. |
| Режим свечи | `icons/candle/<slug>.webp` | WebP | Тот же кадр, оптимизированный для отображения в сцене. |
| Мастер прозрачности | `icons/png/<slug>.png` | PNG | Реальный альфа-контур; используется для тени, света и затемнения. |

Для уже подготовленного Андрея используются те же четыре поля. Его старые
пиксельные размеры не являются нормой для следующей партии: следующие обычные
и candle-файлы нужно ограничивать 600 px по длинной стороне, если качество
исходника не требует иного.

## 4. JSON-контракт

В `data/icons.json` у записи иконы должны быть заполнены пути:

```json
{
  "image": "./icons/<slug>.jpg",
  "preview_image": "./icons/preview/<slug>_preview.jpg",
  "loading_image": "./icons/loading/<slug>_loading.jpg",
  "candle_image": "./icons/candle/<slug>.webp",
  "cutout_master": "./icons/png/<slug>.png"
}
```

`image` остаётся лёгким JPEG для обычных экранов. PNG не показывается как
обычная картинка: он нужен там, где прозрачность действительно работает на
сцену — тень и связанные эффекты свечи.

## 5. Автоматический пакетный процесс

Конвейер находится в `scripts/prepare_icon_assets.py`. Для замены уже
существующей иконы достаточно сохранить новый исходник вне `icons/` и выполнить:

```bash
python3 scripts/prepare_icon_assets.py \
  --slug troica_rublev \
  --source /полный/путь/к/новому-исходнику.jpg
```

Скрипт не меняет исходник. Он сам ограничивает обычный JPEG длинной стороной
600 px, создаёт WebP 480 px с альфа-каналом, PNG-маску, квадратное превью
160×160, пиксельный loading-JPEG 48 px по длинной стороне и обновляет пять
полей записи в `data/icons.json`.

Превью строится по правилу `cover` и затем увеличивается ещё на 10%; поэтому
короткая сторона всегда перекрывает квадрат, а вокруг доски не возникает
пустого поля. В JSON записывается хеш содержимого как query-параметр, чтобы
Safari не оставлял старую картинку в кэше после замены.

Автоматическая альфа убирает только внешнюю чёрную область, которая связана с
краем кадра. Чёрная живопись внутри доски остаётся нетронутой. Чувствительность
задаётся опцией `--black-threshold` (по умолчанию `30`).

Для каждого утверждённого исходника автоматизация должна делать следующее:

1. Присвоить постоянный `<slug>`.
2. Создать мастер PNG с альфой и проверить его контур.
3. Из одного выровненного master crop собрать JPEG для экрана, пиксельный JPEG
   для прогрессивной загрузки, превью и WebP для свечи.
4. Записать пять путей в JSON.
5. Проверить, что все пять файлов существуют и что PNG действительно имеет
   альфа-канал.
6. Открыть режим свечи на узком телефоне, широком телефоне и планшете в
   альбомной ориентации: тень должна брать PNG-альфу, а не натуральный размер
   файла или прямоугольник изображения.

## 6. Критерий готовности

Икона считается готовой только когда:

- каталог использует маленький JPEG;
- экран иконы сначала показывает полноразмерный по пропорциям loading-JPEG,
  растянутый без сглаживания, а затем основной JPEG;
- обычный экран использует JPEG нужного размера;
- свеча использует лёгкое отдельное изображение;
- PNG-маска прозрачна вокруг иконы;
- тень повторяет эту альфу и не обрезается на границах своего слоя;
- JSON содержит все четыре актуальных пути.
